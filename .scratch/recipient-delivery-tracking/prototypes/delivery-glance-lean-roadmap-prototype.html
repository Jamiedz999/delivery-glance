DELIVERY GLANCEScope note 01
Resume-first edition
09 Aug 2026

A portfolio case study in four increments

不是把产品
做小。是先把
证明做完整。

完整产品规格仍然存在；第一版只承担一个清楚命题：一次配送如何被可靠派出、只暴露当前必要位置，并让 Recipient 无账号看懂正在发生什么。

01THE PRODUCT

最终成品是一段三个人都能完成的故事。

Dispatcher · desktop

派一个人，不运营一个市场。

创建 Delivery，看三个最近的 Eligible Couriers，直接 Assignment，并复制 Recipient Link。

Courier · mobile

明确同意分享此刻，不留下路线。

On Duty 与 Location Sharing 分开；前台上报最新点，pickup 后确认 Delivered。

Recipient · mobile

不用登录，一眼知道进度。

安全 Link 打开状态故事；In Transit 才出现地图，并明确 Live、Delayed 或 Unavailable。

PostgreSQL 决定发生了什么。
Memory 只保存此刻在哪里。
SSE 只提醒页面重新看事实。
02THE CADENCE

价值不是在第六周突然出现。

每一个一周 Sprint 都能上线和录 Demo；任何一周停止，仓库仍保持可运行，而不是留下半套基础设施。

WEEK 01Walking skeleton 上线8–10h
WEEK 02内部派单与交付闭环18–22h 累计
WEEK 03Recipient MVP 可用28–34h 累计
WEEK 04Portfolio Core 有证据38–46h 累计
03THE SYSTEM

技术栈服务于一个面试时讲得清的取舍。

ONE WEB APP

React 三角色界面；Recipient 使用 MapLibre 与一个 SSE channel。

ONE BOOT APP

HTTP commands、role security、Haversine ranking、HMAC Link 与 latest-location memory。

ONE POSTGRES

Delivery lifecycle、Assignment uniqueness、accounts 与必要 audit；没有 GPS history。

Core 不使用 Redis、Kafka、PostGIS、WebFlux、microservices 或 Kubernetes。不是因为它们不好，而是当前没有一个被测量过的问题需要它们。

04THE BACKLOG

删减不是遗忘；它变成可以解释的 Future Issue。

#13ETA需要 provider contract、失败语义与成本证据。
#14Link recovery恢复暴露链接的能力值得独立验收。
#15Exceptions重派与 Undeliverable 会扩展整个状态矩阵。
#16Service Zones真实区域边界出现后才值得加入 polygon。
#17Matching RoundTop-three consent flow 是一整个产品增量，不是小按钮。
#18Scale experiment先找到瓶颈，再单独验证 Redis、PostGIS 或 WebFlux。
#19Kafka evaluation必须先有独立 durable consumer；raw location 永远禁止。
05THE CLAIM

什么时候可以写进简历？

Sprint 3：可以展示并说明“active MVP”。
Sprint 4：公开 Demo、自动化证据、README、图和演示视频齐全，才描述为 completed project。

Built and deployed a recipient-first last-mile tracker with database-enforced atomic Courier assignment, privacy-minimised foreground geolocation and SSE live updates through secure no-account Tracking Links.
